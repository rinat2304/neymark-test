# Задание 2 — Расписание междугородних автобусов

## Задача

Спроектировать структуру БД для расписания междугородних автобусов и SQL-запрос для электронного табло, показывающего следующие 15 рейсов с заданной остановки.

В качестве СУБД используется MySQL 8.4.

## Структура БД

Основные сущности:

* `cities` — города;
* `stops` — остановки;
* `buses` — автобусы;
* `routes` — логические маршруты;
* `route_stops` — остановки маршрута в заданном порядке;
* `trips` — конкретные рейсы с датой и временем отправления;
* `trip_stops` — расписание конкретного рейса по остановкам.

### Почему отдельно `routes` и `trips`

`routes` описывает постоянную схему маршрута.

Например:

```text
Москва → Тула → Орёл → Курск
```

`trips` описывает конкретный рейс по этому маршруту:

```text
01.10.2026 06:30, автобус A001AA
```

Это позволяет одному маршруту иметь любое количество рейсов в разные даты и времена.

## Основной запрос

Основной запрос находится в `queries.sql`.

Параметры:

* `:stop_id` — идентификатор остановки;
* `:from_time` — момент времени, начиная с которого нужно показывать отправления.

Запрос:

1. находит рейсы, проходящие через указанную остановку;
2. отбирает только отправления начиная с указанного момента;
3. сортирует их по времени отправления;
4. возвращает следующие 15 рейсов.

Для электронного табло используется именно `departure_at`, так как требуется показать время отправления с конкретной остановки.

## Индексы

Для основного запроса используется составной индекс:

```sql
CREATE INDEX idx_trip_stops_stop_departure
    ON trip_stops (stop_id, departure_at, trip_id);
```

Порядок полей соответствует условиям запроса:

1. `stop_id` — поиск рейсов конкретной остановки;
2. `departure_at` — диапазон по времени;
3. `trip_id` — дополнительное поле для стабильной сортировки при одинаковом времени отправления.

Первичные и уникальные ключи остальных таблиц также создают необходимые индексы для соединений:

* `trips.id`;
* `routes.id`;
* `buses.id`;
* `trip_stops.trip_id`;
* уникальный `buses.plate_number`.

## Ожидаемый план выполнения

План можно проверить командой `EXPLAIN`, которая находится в `explain.sql`.

Ожидается, что MySQL будет использовать индекс:

```text
idx_trip_stops_stop_departure
```

для таблицы `trip_stops`.

Основной этап должен выглядеть логически следующим образом:

```text
trip_stops
    ↓
индекс по (stop_id, departure_at, trip_id)
    ↓
отбор нужной остановки
    ↓
отбор отправлений >= :from_time
    ↓
получение первых 15 записей
    ↓
JOIN trips
    ↓
JOIN routes
    ↓
JOIN buses
```

Для соединений с `trips`, `routes` и `buses` ожидается использование индексов первичных ключей и точечных поисков по `id`.

За счёт фильтра по `stop_id`, диапазона по `departure_at` и `LIMIT 15` не требуется полный просмотр всей таблицы `trip_stops`.

Фактический план зависит от статистики таблиц, количества данных и версии оптимизатора MySQL. Поэтому `EXPLAIN` используется для проверки реального выбора индексов, а не только для предположения о плане.

## Тестовые данные

`seed.sql` содержит:

* 5 городов;
* 10 остановок;
* 20 автобусов;
* 6 маршрутов;
* 19 конкретных рейсов.

Граф маршрутов произвольный: маршруты могут пересекаться и проходить через одни и те же города.

## Файлы

* `schema.sql` — DDL базы данных;
* `seed.sql` — тестовые данные;
* `queries.sql` — запрос электронного табло;
* `explain.sql` — индекс и `EXPLAIN`.

## Допущения

* Один рейс выполняется одним автобусом.
* Остановка имеет принадлежность к одному городу.
* Порядок остановок внутри маршрута задаётся через `stop_order`.
* Время отправления с каждой остановки хранится отдельно.
* Для электронного табло используются именно отправления (`departure_at`), а не время прибытия.
* Для тестовых данных `seed.sql` предполагается запуск на пустой базе данных.
